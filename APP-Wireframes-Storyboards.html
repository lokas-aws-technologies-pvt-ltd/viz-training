Wireframes & storyboards for the Igiver training platform

Low-fidelity on purpose: these fix what each screen does and which schema fields it touches, not colors or final layout. Every frame is annotated with its reads and writes against the data structure, and every storyboard step points at the frame it happens on.

  • Responsive web app — desktop for admin, phone for trainers
  • Logins: Admin · Trainer · Placement officer
  • Coordinator enters all entrance scores — no panelist logins
  • Students, panel members, colleges: no accounts (matches schema)

How to read these

Sheet codes (W-01…) are stable references — storyboards and annotations cite them. Red Q-chips link to the open-questions list at the end.

content
Dashed box = placeholder / content region. Size and copy are indicative only.
ActionPrimary
Solid outline = interactive control. Filled = the screen's primary action.
Crossed box = file upload or media (photos, PDFs, certificates).
billing.rate_applied
Blue mono = a real column from the schema this UI reads or writes.
Q4
Red chip = something the schema can't answer — see open questions.

Open questions10 — none block wireframing; all block build

Things neither the schema nor our decisions so far can answer. Each has the default the wireframes currently assume — correct any that are wrong.

  1. How do candidates arrive in the system?

    W-05 assumes both single-entry and a CSV import from the college. If colleges send spreadsheets, the import needs a defined column format. Assumed: CSV import exists.

  2. Is selection strictly top-N by rank, or can the coordinator override?

    W-07 draws a cutoff that pre-selects, with per-row override toggles. If policy is strict rank order, the toggles go away. Assumed: override allowed.

  3. Is the deposit a fixed standard amount?

    The schema stores it per student, which permits variation. If it's always the same figure, W-09 pre-fills it and the field locks. Assumed: standard amount, editable.

  4. Does the Zoho / nonZoho track change what's taught?

    Nothing in the schema links track to subjects. If Zoho-track students get different subjects, a link table is needed and W-12's topic picker must filter by track. Assumed: track is a label only, for now.

  5. Who declares availability slots?

    Colleges have no login, so W-12 assumes the college phones/emails and an admin types it in. Fine at current scale; a college portal is a future option. Assumed: admin enters.

  6. Who has the final say on a session's actuals?

    W-17 lets the trainer record actual times and status; W-13 lets an admin override. If billing disputes matter, overrides should be logged. Assumed: trainer records, admin may override.

  7. Are certificates generated by the system or outside it?

    The schema stores a template_url, which suggests generation, but no output field exists for the finished certificate PDF. If the system generates, add an issued_certificate_url. Assumed: recorded in-system, generated outside for v1.

  8. What's the billing period convention?

    W-15 assumes calendar-month invoices per payee. The schema allows arbitrary periods. Assumed: monthly.

  9. When does a student become eligible for placement?

    W-22's student picker needs a rule: only completed students, or also in_progress near course end? Interviews often start before courses finish. Assumed: in_progress and completed both appear.

  10. What happens to the deposit on dropout?

    The spec ties refund to completion; dropout refund policy is unstated. S-10 ends on this decision. Assumed: case-by-case, recorded in notes — but a policy would be better.
